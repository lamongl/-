# 从需求到可用成品

用于复杂演示、报告、工作簿或其他需要组织内容的成品。简单、明确的编辑在工作台完成一题方向确认即可。

## 分轮澄清

先读材料，再列出已有答案、未决问题及默认选择。只向用户询问会改变内容或验收的事项：

| 需要确定什么 | 合适的问题 | 对制作的作用 |
|---|---|---|
| 用途与受众 | 看完后希望对方理解、决定或完成什么？ | 选择主线、解释深度和结论 |
| 交付条件 | 使用时长、语言、格式、篇幅、是否需要可编辑源文件？ | 控制容量，避免做完再返工 |
| 内容重点 | 材料中哪一个问题最需要说服或解释？ | 分配证据、例子和重点篇幅 |
| 证据边界 | 缺失的数据是否有原始来源？不能补充时如何处理？ | 区分事实、作者观点与假设 |
| 表现方式 | 有必须沿用的模板、图表、风格或展示条件吗？ | 选择能实际实现的呈现方式 |

每轮1至3题，通常先给一组基础问题，再围绕材料中具体内容继续。复杂任务可问两到三轮，不设必须问满的总题数。完成至少一轮工作台问答，并满足以下条件即可开始：用途明确，交付条件明确，主线可确定，关键事实与约束不存在未处理冲突。停止追问次要偏好。

每题围绕一个决定；选项写出内容差异。提供“请AI建议”时，AI应依据材料选择并承担组织工作，不能再把同一决定换个问法退回用户。若用户选择冲突（例如五分钟讲完大量详细章节），指出容量冲突，询问保留重点还是延长时长。

答辩示例：已知五分钟、八页、英文页面和中文讲稿，就把这些信息合并为方向确认，不再逐项重复询问。若论文缺乏原创实证数据，可以问“答辩主线更希望突出哪部分？”，给出与原文一致的“角色、学习和责任的整体框架”“学习路径的具体建议”“请AI根据论文推荐”。不把文献讨论包装成实证成果。

## 制作方案

内部保留六项简短决定，随已确认回答更新：

1. **成功标准**：受众最终应理解什么或完成什么；哪些要求必须满足。
2. **内容主线**：按问题、证据、解释、贡献与限制组织，而非机械照搬章节。
3. **证据对应**：核心结论依赖什么来源、计算或原始材料；缺口如何呈现。
4. **表达方式**：为各部分选择文字、图示、表格、实例或交互；每种形式服务于具体内容。
5. **交付规格**：格式、容量、语言、可编辑性、备注及必要附件。
6. **验证方法**：如何检查内容、数字、文件功能与实际阅读效果。

用户只需看懂必要的方向选择，不需要阅读内部提示词或完整方案。不要让每个任务都经历批准大纲、批准初稿、批准定稿。

## 按成品选择质量重点

- **答辩PPT**：研究问题、方法性质、核心论点、证据、贡献与局限均需得到恰当覆盖；给重点论点足够讲述时间。比较关系用对比图或表格，过程用流程图，数字需有单位、时间与出处。避免把整篇论文压成密集文字，也避免空泛口号和只有标签的装饰图。讲稿与当前页对应；备用问答针对论文最容易受质疑的地方，并明确未完成的研究。
- **报告与文档**：开头回应读者的问题；结论能追溯到事实或分析；建议有适用条件；图表和段落互相补充。检查标题层级、分页、表格和来源。
- **工作簿**：定义口径、单位、时间和缺失值；区分输入、计算与结果；核对公式、汇总和样例值，提供足够的使用说明。
- **代码与项目**：先跑通用户的关键操作，验证输入、状态和输出；交付实际运行方法与必要文件，不以截图代替功能。

## 交付前检查

先检查会导致成品不可用的问题：遗漏硬性要求、错误事实或计算、无依据结论、缺页、损坏文件、不可执行功能。然后检查结构、可读性和风格。

按目标格式实际打开、渲染或运行。视觉作品逐页检查文字溢出、字号、对齐、留白和图表辨识度。发现问题只重做受影响部分，再执行相关检查；已通过的无关检查不机械重复。

检查通过不等于质量优于未使用Skill。比较效果时记录相同材料、相同完整需求、模型和底层工具条件，分别制作后再检查；报告不足与不确定性，不把单次实验写成稳定提升。
